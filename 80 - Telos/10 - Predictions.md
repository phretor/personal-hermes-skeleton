# Predictions

Predictions you're willing to make about the future of the fields you work in. The point isn't to be right. The point is to (a) force concrete commitments instead of fuzzy "I think X matters," (b) calibrate forecasting over time, and (c) leave artifacts the future-me can compare against the actual outcome.

## Format

Each prediction:

- **Statement**: one or two sentences, concrete enough to be falsifiable.
- **Horizon**: when by (e.g., "by 2028", "within 5 years", "before the next major release in your field").
- **Confidence**: `low` / `medium` / `high`. Use `high` sparingly; default `medium`.
- **Why**: the reasoning. Saves future-me from "why did I think that?"
- **Resolution**: left blank initially; filled when the horizon hits (correct / wrong / partially / unfalsifiable in hindsight).

## How this file is used

- **Add when a thesis solidifies**: writing it down forces sharper thinking. If it can't be written falsifiably, it isn't yet a prediction.
- **Quarterly review**: sweep for predictions whose horizon has passed; resolve them.
- **Yearly review**: calibration check during the year-end Telos review. Of last year's "high-confidence" predictions, what fraction came true? Adjust internal weighting.
